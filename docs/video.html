Transcript

What the video says

  1. A spreadsheet formula can run, point to the wrong cells, and quietly return the wrong answer. FormulaBench is built for that risk.
  2. Qwen proposes the spreadsheet answer. FormulaBench controls what it sees, what it may change, and how correctness is judged.
  3. It begins with a plain-English request and the original workbook, plus the exact sheets and cells that need answers.
  4. FormulaBench reads formula text and cached values, then turns relevant sheets, ranges and nearby cells into a compact evidence pack.
  5. That evidence goes to Qwen three point eight, twenty-seven B, through Tinker: one logical sample, temperature zero, thinking disabled, and no model-level repair loop.
  6. Qwen interprets the request and proposes formulas or values for exact worksheet addresses. It does not freely operate Excel.
  7. Deterministic checks require complete coverage, permitted addresses and valid data types. A narrow static screen blocks explicit external references and defined executable functions.
  8. A valid response is written into a fresh workbook, then reopened to verify structure and assigned cells. A failure returns the original workbook unchanged, never partly edited.
  9. The production inference path never opens gold. After generation, LibreOffice recalculates the file, then a separate evaluator compares every target value with the golden answer.
  10. The frozen four-hundred-task result used untuned Qwen. It passed one hundred thirty-three tasks: thirty-three point two five per cent, with forty point five six per cent cell accuracy.
  11. Later, FormulaBench trained a rank-thirty-two LoRA on fifty-nine development examples for fifteen steps. It adds a compact correction, not a full retraining of twenty-seven billion parameters.
  12. On fifteen development-validation tasks, base Qwen passed seven and Qwen plus LoRA passed nine. That is real but limited: not a new four-hundred-task score, and not private-benchmark proof.
